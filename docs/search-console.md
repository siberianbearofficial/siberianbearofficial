# Submitting the two domains to search engines

Everything a crawler needs is generated by `npm run build`. What is left are the
two steps only the domain owner can do: proving ownership and pressing submit.

## What the build already produces

| Surface | URL | Notes |
| --- | --- | --- |
| CV, Russian | `https://aleksei-orlov.ru/` | domain default |
| CV, English | `https://aleksei-orlov.ru/en/` | |
| Resume, Russian | `https://aleksei-orlov.ru/resume/` | source of `Aleksei-Orlov-Resume-RU.pdf` |
| Resume, English | `https://aleksei-orlov.ru/en/resume/` | source of `Aleksei-Orlov-Resume.pdf` |
| Services, English | `https://aleksei-orlov.dev/` | domain default |
| Services, Russian | `https://aleksei-orlov.dev/ru/` | |

Each page carries a self-referencing `<link rel="canonical">`, `hreflang`
alternates for `ru`, `en`, and `x-default`, a language-specific `<title>` and
meta description, Open Graph and Twitter cards pointing at a generated
1200x630 image, and JSON-LD (`Person` on the CV, `ProfessionalService` plus
`FAQPage` on the services site).

`sitemap.xml` and `robots.txt` are served per domain by nginx out of
`sitemap-ru.xml` / `sitemap-dev.xml` and `robots-ru.txt` / `robots-dev.txt`.

## Google Search Console

1. Add **two separate properties**, one per domain. A domain property
   (`aleksei-orlov.ru`, verified by DNS TXT record) is the better choice: it
   covers `www`, both schemes, and every subdomain at once.
2. If DNS is inconvenient, use a URL-prefix property and the HTML-file method:
   drop the file Google gives you into `public/` in this repository and
   redeploy. Anything in `public/` is copied to the site root, so
   `public/google<token>.html` is served at
   `https://aleksei-orlov.ru/google<token>.html`.
3. Under **Sitemaps**, submit `sitemap.xml` for each property. Do not submit
   `sitemap-ru.xml` or `sitemap-dev.xml` directly — those are the internal
   filenames, and the canonical path is what the robots.txt points at.
4. Use **URL Inspection → Request indexing** once per language entry point so
   the first crawl does not wait on discovery.

## Bing Webmaster Tools

1. The fastest route is **Import from Google Search Console**, which carries
   over ownership verification and the sitemaps.
2. Otherwise verify with the XML file method, again by adding
   `public/BingSiteAuth.xml` and redeploying.
3. Submit the same two `sitemap.xml` URLs.

## After the first crawl

- Check that Google reports the hreflang pairs without "no return tag" errors.
  Both directions are emitted, so an error there means a URL changed and the
  route table in `scripts/lib/routes.mjs` and `nginx/default.conf` drifted apart.
- Confirm the `.ru` property reports the Russian pages as the indexed
  canonicals and `.dev` reports the English ones — that is the domain-default
  rule working as intended.
